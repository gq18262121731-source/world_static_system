## 一、先解释数据和实验中的基本名词

### 1.1 我们观察的是什么？

| 名词 | 通俗解释 | 本实验中的含义 |
| --- | --- | --- |
| 生命体征／体征 | 用来描述身体状态的可测量指标 | 使用心率、体温、血氧和收缩压四项数值 |
| 心率（HR，Heart Rate） | 心脏每分钟跳动多少次 | 单位 bpm，即每分钟次数 |
| 体温 | 测得的身体温度 | 单位为摄氏度 ℃；这里是模拟生成的温度值 |
| 血氧（SpO₂） | 常用于表示外周血氧饱和度，即血液携氧状态的一项估计指标 | 用百分数表示；不等于空气中的氧气比例 |
| 收缩压（SBP，Systolic Blood Pressure） | 心脏收缩时的动脉血压，通常所说的“高压” | 单位 mmHg，即毫米汞柱；本实验只使用收缩压这一项血压数值 |
| 时间序列／时序 | 按时间先后排列的一串数据 | 模型可以看到数值如何随时间变化 |
| 多变量 | 同时观察多项数值 | 同一时刻同时观察四项体征 |
| 特征 | 算法接收或计算出来、用来描述数据的数值 | 四项体征是原始特征；一段数据的均值、变化速度也可以作为特征 |
| 窗口／样本窗口 | 一次送给算法判断的一小段数据 | 一个窗口包含 24 个时间点，每点有四项体征，相邻点假设间隔 5 分钟 |
| 窗口级指标 | 把整段窗口作为一个判断单位来计算成绩 | 720 个窗口就是 720 次判断，不是 720 位老人，也不是 720 次真实疾病事件 |

本实验的窗口是分别生成的模拟片段，不是一条连续监护记录。因此，不能把窗口误报率直接换算成“每位老人每天误报多少次”。

### 1.2 数据从哪里来？“正常”和“异常”是什么意思？

| 名词 | 通俗解释 | 本实验中的含义 |
| --- | --- | --- |
| 合成数据 | 按预先设定的规律和随机变化，由程序生成的数据 | 模拟不同个体、活动和休息、测量波动，以及人为加入的异常变化；没有使用真实老人记录 |
| 测量噪声 | 测量过程中出现的小幅随机波动 | 正常模拟数据也包含噪声，避免正常数据过于整齐 |
| 统计异常 | 数据的数值或变化方式偏离预先定义的正常规律 | 可能是数值偏移、指标之间的关系变化或时间顺序变化；不自动等于疾病 |
| 标签 | 为了检查算法判断是否正确，事先记录的答案 | 正常窗口记为 0；加入指定异常变化的窗口记为 1 |
| 异常占比 | 所有被评价窗口中，异常窗口所占的比例 | 本次测试人为设为 25%，不代表现实生活中老人的异常发生率 |
| 离线实验 | 先准备数据，再在电脑上运行算法进行比较 | 本图来自一次独立实验，不是正在接收手环数据的现场监护结果 |
| 临床验证 | 用真实人群和可靠的医学评价依据，检查方法的实际有效性 | 本实验尚未完成这一验证，所以图上标有“非临床验证” |

本实验先决定向哪些窗口加入哪种异常，再让算法去识别。标签不由某个参赛算法的输出决定，避免“用自己的答案证明自己正确”。

### 1.3 怎样避免把练习成绩当成考试成绩？

| 名词 | 通俗解释 |
| --- | --- |
| 模型训练 | 用已有数据调整算法内部的参数，让它学习数据中的规律 |
| 推理 | 使用已经确定的算法参数，对新输入给出结果 |
| 训练集 | 学习用的“练习题”；本实验训练检测器时只使用正常窗口 |
| 验证集 | 开发阶段用于选择模型和判断界限的“模拟考试题” |
| 测试集 | 方法确定后用于最终测量的“正式考试题” |
| 独立测试对象 | 测试中的合成对象不属于训练或验证中的对象；但各组仍由同一类模拟规律生成 |
| 数据泄漏 | 把测试信息提前用来训练或调参，使成绩看起来过好 |
| 泛化能力 | 对学习时没有见过的新数据仍能有效判断的能力；合成数据内部的表现不能直接等同真实人群中的表现 |
| 无监督／仅正常数据训练 | 检测器学习时无需逐个学习各种异常类型；本实验仍使用异常标签选择验证阈值和计算测试成绩，因此整个实验并非完全不需要标签 |

这里的“独立对象”允许为新对象提供一段另外生成的正常历史，用来了解其平时水平。这段历史不包含待判断窗口。

## 二、解释主图算法与技术补充中的相关名称

先解释主图所用的方法，同时解释技术补充中出现的 AE，以便后面阅读完整对照结果。

### 2.1 先认识共同用到的几个概念

| 名词 | 通俗解释 |
| --- | --- |
| 个人基线 | 一个人在已知正常状态下，平时大致处于什么水平、通常波动多大 |
| 均值 | 一组数值的平均数，用来概括一般水平 |
| 标准差 | 描述数值围绕平均数波动多大的量；越大表示分散程度越大 |
| 标准化 | 把不同单位、不同波动大小的数值换到可比较的尺度；本实验用“当前值减去个人均值，再除以个人标准差” |
| 阈值 | 做出“正常／异常”判断的分界线；超过界限或低于界限就触发判断 |
| 异常分数 | 描述某个窗口有多异常的连续数值；本实验统一规定越大越异常，它不是患病概率 |
| 神经网络 | 由许多可调整的数学运算组成的模型，通过训练学习输入中的规律 |
| 编码器／解码器 | 编码器负责把原数据压缩成较少的数字；解码器负责用这些数字还原原数据 |
| 重构 | 按学到的规律还原输入数据；不是预测未来尚未发生的数据 |
| 重构误差 | 还原结果与原始数据的差异；差异大说明模型较难还原该输入 |
| MSE（Mean Squared Error，均方误差） | 把各处误差分别平方，再求平均；本实验用整个标准化窗口的均方重构误差作为两种序列模型的异常分数 |

### 2.2 固定阈值

**意思：提前设定体征界限，逐点检查有没有越界。**

本实验沿用项目较早的关注界限：心率小于 50 或不低于 100、体温小于 35 或不低于 37.5、血氧不高于 94、收缩压小于 90 或不低于 140。窗口里任何一点触发，即将该窗口判为异常。

这些数值是本次复用的项目实验规则，不是本文给出的医疗建议。

它的判断依据直观、容易解释；对于数值没有越界、但变化方式发生异常的情况，单点规则可能缺少判断依据。后面的结果部分会检验它在本次数据上的实际表现。

### 2.3 个人 Z-score

**Z-score，中文常称标准分数：当前值偏离个人平均水平，相当于多少个标准差。**

计算思路是：

`Z-score =（当前值 − 个人正常均值）÷ 个人正常标准差`

例如，假设某项数值平时均值为 70、标准差为 5，当前为 80，那么 Z-score 为 2。这个例子只用于解释计算，不是本次实验结果或医学判断。

本实验取一个窗口中四项指标的最大绝对 Z-score，再用验证集选择异常分界线。它体现了个人差异，但这一具体实现没有直接学习多个指标之间的完整时间关系。

实现中还给分母设置了最小值，避免正常波动很小时，微小变化被过度放大。

### 2.4 Isolation Forest：孤立森林

**“孤立”是把一个样本单独分出来；“森林”是组合许多棵随机切分数据的树。**

可以把一堆样本想象成散落的点：算法随机选择一项特征和一个切分位置，反复把点分组。明显远离其他样本的点，往往较少切几次就能单独分出来，因此可能被视为异常。

本实验使用 200 棵树。每个窗口先提取均值、标准差、最小值、最大值、斜率和相邻变化大小。其中，**斜率**表示整体上升或下降的速度。

所以，本实验的孤立森林也能利用部分时间变化信息，不能简单说成“完全不看趋势”。它使用的是窗口摘要，而非逐个时间点输入的序列模型。[算法说明](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.IsolationForest.html)

### 2.5 LSTM：长短期记忆网络

**LSTM 全称 Long Short-Term Memory，中文为长短期记忆网络，是用于处理序列的一类神经网络。**

它按时间先后读取数据，并保留对后续判断有用的信息。通俗地说，它可以同时参考“现在是多少”和“前面是怎样变化到这里的”。

在本实验中，LSTM 用于编码和还原整个体征窗口。名称中的“长短期”不代表本次实验已经证明能记住几天或几个月；本次实际输入仍然只有 24 个时间点。

### 2.6 AE 与 LSTM-AE

**AE 全称 Autoencoder，中文为自编码器。**

它先压缩输入，再尝试还原输入。**潜变量**就是压缩后用来概括输入的那组数字，可以把它理解为一段数据的简短“摘要”。

**LSTM-AE** 就是使用 LSTM 处理时间序列的自编码器。本实验让它学习正常窗口的还原方式，再根据新窗口的重构误差判断异常。

这里的思路是：正常规律学得较好时，一些偏离这些规律的窗口可能更难还原。但模型也可能还原某些异常，所以“能重构”与“检测准确”仍需分别检查。

### 2.7 VAE 与 LSTM-VAE

**VAE 全称 Variational Autoencoder，中文为变分自编码器。**

普通 AE 用一组确定的压缩数字描述输入；VAE 用一个**概率分布**描述压缩数字可能出现的位置和分散程度。概率分布可以理解为“哪些取值更容易出现，哪些较少出现”的规则。

与此相关的三个名词是：

- **采样**：按照这个分布抽取一组数字。本实验训练 VAE 时会采样。
- **正则化**：训练中增加约束，避免模型只顾记住练习数据。只在练习数据上表现好、换新数据就差，称为**过拟合**。
- **KL 散度（Kullback–Leibler divergence）**：衡量两个概率分布差异的一种量。VAE 训练用它约束压缩数字的分布；它不是检测准确率。

**LSTM-VAE** 把 LSTM 的序列处理方式与 VAE 的压缩、还原和分布约束结合起来。本实验推理时使用**后验均值**，即“根据当前输入估计出来的分布中心”，避免每次重新采样导致同一输入的分数随机变化。

因此，VAE 带有概率分布，并不意味着它输出了经过验证的患病概率。是否比普通 AE 更好，也必须看实验，不能只根据模型名称判断。[VAE 原始论文](https://arxiv.org/abs/1312.6114)

## 三、解释图中的评价指标、符号和异常类型

### 3.1 先区分四种判断结果

本实验把异常叫作**正例**，把正常叫作**负例**。这两个词只是计算约定，不表示好坏。

| 实际标签 | 算法判断 | 名称与缩写 | 通俗含义 |
| --- | --- | --- | --- |
| 异常 | 异常 | 真阳性 TP（True Positive） | 找到了异常 |
| 正常 | 异常 | 假阳性 FP（False Positive） | 误报了正常窗口 |
| 异常 | 正常 | 假阴性 FN（False Negative） | 漏掉了异常 |
| 正常 | 正常 | 真阴性 TN（True Negative） | 正确放过正常窗口 |

把这四种数量排成表，称为**混淆矩阵**。精确率、召回率、误报率和 F1 都可以从这张计数表得到；AP 还需要各窗口的连续分数。

### 3.2 Precision：精确率，又称查准率

**它问的是：被算法判为异常的窗口中，有多少真的带有异常标签？**

`精确率 = TP ÷（TP + FP）`

精确率越高，表示被判异常的结果中，正确的比例越高。它的分母是“算法判出的异常”，不是全部真实异常。

### 3.3 Recall：召回率，又称查全率

**它问的是：所有真实异常窗口中，有多少被算法找到了？**

`召回率 = TP ÷（TP + FN）`

召回率越高，漏掉的异常越少。**漏报率**就是 `1 − 召回率`。图中的“召回率 ↑”表示这个指标通常越高越好。

### 3.4 FPR：误报率

**FPR 全称 False Positive Rate：所有正常窗口中，有多少被错判为异常？**

`误报率 = FP ÷（FP + TN）`

图中的“误报率 ↓”表示越低越好。

需要分清两个不同问题：

- 误报率看的是“正常窗口被打扰的比例”。
- `1 − 精确率` 看的是“被判异常的结果中，有多少是误报”。

两者的分母不同，不能互换。本图的误报率也不是每天发出多少条告警。

### 3.5 F1：综合精确率与召回率的分数

**F1 是精确率和召回率的调和平均。** 调和平均是一种平均方式，会让其中较低的一项明显拉低总体分数，从而避免只看某一项的好成绩。

`F1 = 2 × 精确率 × 召回率 ÷（精确率 + 召回率）`

也可以直接用计数计算：

`F1 = 2 × TP ÷（2 × TP + FP + FN）`

F1 的范围是 0～1，通常越高越好。它与 **Accuracy（总体准确率）** 不同；总体准确率是 `(TP + TN) ÷ 全部窗口数`。

例如，假设 100 个窗口中只有 1 个异常，全部判断为正常也有 99% 的总体准确率，却一个异常都没有找到。因此，本图重点展示 F1、召回率和误报率。

**F1 为 0.776，不能表述为“老人健康评分准确率为 77.6%”。**

### 3.6 PR 曲线、AP 和 PR-AUC

**PR** 中的 P 是 Precision，R 是 Recall。不断改变异常判定阈值，就能得到一组不同的精确率和召回率，把这些点画出来就是 **PR 曲线**。

**AUC** 全称 Area Under the Curve，即曲线下面积；**PR-AUC** 一般用于概括整条 PR 曲线的表现。

**AP** 全称 Average Precision，即平均精确率。它按照“每一步新增多少召回”进行加权，汇总这些位置的精确率。通俗理解：把窗口按异常分数从高到低排列，AP 衡量真正异常能否较集中地排在前面。

本图用 AP 作为 PR 曲线的汇总口径，图注写为“PR-AUC 使用 AP 计算”。**AP 与直接用梯形面积公式计算的 PR 曲线面积不是完全相同的计算方法。** AP 的范围是 0～1，越高通常表示排序区分效果越好。[AP 官方定义](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.average_precision_score.html)

理解时注意：

- F1 对应本次选定的一个判断阈值。
- AP 汇总多个阈值下的表现。
- AP 不是固定阈值下的召回率，也不是健康分准确率。
- AP 受异常占比影响，比较时应使用同一测试数据和相同异常占比。

### 3.7 随机种子、均值、标准差和误差线

**随机种子**是控制随机过程起点的编号，相同程序、配置和条件下可据此重复实验。它不是对象编号，也不是训练次数。

本实验用三个预先固定的种子，生成三组数据并分别训练、评估。每种方法因而有三份结果。

- **均值**：三次结果的平均水平。
- **样本标准差**：用这三份结果计算的波动大小，计算时使用样本标准差的形式。
- **均值 ± 标准差**：同时展示水平与波动，例如 `0.776 ± 0.012`。
- **误差线**：条形末端或圆点旁的横线，对应均值左右各一个标准差；图中的数值标签只写均值。

误差线短，只能说明这三次运行的指标变化较小。它不是每次运行的保证范围，也不是医学判断的误差范围。

**统计显著性**是通过统计检验判断观察到的差异是否足以超出随机波动的一类结论。本次没有进行这种检验，不能仅凭均值差一点或误差线长短，就宣称某方法普遍更优。

### 3.8 热图与四类异常

**热图**是用颜色深浅表示数值大小的表。图中颜色越深表示该类异常的召回率越高；颜色与体温高低无关。

| 图上的名称 | 数据中具体做了什么 | 应当怎样理解 |
| --- | --- | --- |
| 持续偏移 | 从窗口中的某个时刻起，让若干指标持续高于或低于原来的水平 | 关注“偏离以后一直没有回去”的模式 |
| 渐进漂移 | 让偏移程度随时间逐渐增加 | 关注“逐渐变化”的模式；检出这种模式不等于已经证明能提前几分钟预警 |
| 指标关联异常 | 把其中一项指标在时间上错位，其他指标保留原顺序 | 单项数值范围可能仍然相似，但它与其他指标的同步关系被改变 |
| 时序模式异常 | 把一段数据的时间顺序重新排列，四项体征在每个时刻仍一起移动 | 保留原有数值和同一时刻的组合，但改变前后连续性 |

后两类是为了考察识别数据关系与时间模式的能力，不能直接解释成某一种真实疾病。它们可能不改变数值范围，单点阈值自然较难覆盖；四类异常等量安排也会影响最终综合排名。

### 3.9 比较结果时还会用到的几个词

| 名词 | 解释 |
| --- | --- |
| 百分点 | 两个百分数直接相减后的差值，例如 30% 到 40% 是增加 10 个百分点；与“相对增长 10%”不同 |
| 阈值校准 | 使用验证数据选择一个合适的异常判定界限；不表示已经校准了患病概率 |
| 分位数 | 把分数从小到大排列，取指定比例处的值；95% 分位数大致表示 95% 的分数在它以下 |
| JSON（JavaScript Object Notation） | 用字段名称和数值保存结构化记录的一种文本格式；本实验用它保存可核对的结果 |
| 缓存 | 把已经算出的结果保存起来，下次直接读取；缓存回放不是一次新的训练实验 |

至此，图中名称及下文使用的主要专业术语已经解释完毕，下面开始看实际结果。

测试中四类异常各 45 个窗口。三个种子为 **11、23、37**，全部保留，最后分别计算各项指标的均值和标准差。

每位合成对象另有 16 个正常校准窗口，用来计算个人基线。校准数据与待测窗口分开，训练、验证、测试对象也分开。

### 4.2 主图的阈值选择有什么区别？

- 固定阈值这一行使用前面说明的项目预设关注界限。
- 主图中的其他三种方法使用验证集，选择使验证 F1 最大的阈值，再固定下来评价测试集。技术补充中的 LSTM-AE 也采用这一选择方式。
- 固定阈值的 AP 使用到界限的连续距离分数计算，F1 使用原预设界限。

因此，主图展示的是“预设规则”与“经验证集校准的方法”的对比。它不是所有方法都已调整到相同误报率的对比。

## 六、实际对比效果

### 6.1 主图整体结果表：与三种基础方法对比

下表与主图对应。F1、AP 为均值 ± 标准差；召回率和误报率为均值。

| 方法 | F1 ↑ | AP ↑ | 召回率 ↑ | 正常窗口误报率 ↓ |
| --- | ---: | ---: | ---: | ---: |
| 固定阈值 | 0.333 ± 0.039 | 0.409 ± 0.057 | 29.81% | 16.54% |
| 个人 Z-score | 0.591 ± 0.014 | 0.665 ± 0.009 | 45.19% | 2.59% |
| 孤立森林 | 0.643 ± 0.019 | 0.727 ± 0.004 | 60.93% | 9.38% |
| LSTM-VAE | 0.776 ± 0.012 | 0.866 ± 0.021 | 68.52% | 2.65% |

差值在下面根据未四舍五入的原始记录计算，所以可能与直接减表中三位小数的结果略有区别。

### 6.2 LSTM-VAE 与固定阈值相比

- F1 从约 0.333 提高到 0.776，增加 **0.4435**。
- AP 从约 0.409 提高到 0.866。
- 召回率从 29.81% 提高到 68.52%，增加 **38.70 个百分点**。
- 误报率从 16.54% 降到 2.65%，减少 **13.89 个百分点**。

在本次模拟分布和判定设置下，LSTM-VAE 找到了更多异常，同时误判的正常窗口更少。这支持“体征历史和序列模式能够补充固定规则”的展示结论。

不能把这些差值直接说成真实老人监测中的提升，也不能忽略两者阈值选择方式的区别。

### 6.3 LSTM-VAE 与个人 Z-score 相比

- F1 增加约 **0.1847**。
- 召回率从 45.19% 提高到 68.52%，增加 **23.33 个百分点**。
- 误报率为 2.65%，与 Z-score 的 2.59% 接近，实际上略高约 **0.06 个百分点**。

适合这样理解：在较接近的误报水平下，LSTM-VAE 在本次数据中检出了更多异常。

不能说“LSTM-VAE 的误报率比所有传统方法都低”，因为 Z-score 的平均误报率稍低。

### 6.4 LSTM-VAE 与孤立森林相比

- F1 从约 0.643 提高到 0.776，增加约 **0.1330**。
- AP 从约 0.727 提高到 0.866。
- 召回率增加 **7.59 个百分点**。
- 误报率减少 **6.73 个百分点**。

整体指标上 LSTM-VAE 表现更好，但不能据此说每一类异常都更好；下一节可以看到时序模式异常中的反例。

### 6.5 技术补充：LSTM-VAE 与 LSTM-AE 的模型对照（不在主图）

主图聚焦三种基础方法。本节单独检查 VAE 的额外设计是否带来收益，两行均取自相同的完整实验记录：

| 方法 | F1 ↑ | AP ↑ | 召回率 ↑ | 正常窗口误报率 ↓ |
| --- | ---: | ---: | ---: | ---: |
| LSTM-AE | 0.787 ± 0.035 | 0.875 ± 0.021 | 70.56% | 2.84% |
| LSTM-VAE | 0.776 ± 0.012 | 0.866 ± 0.021 | 68.52% | 2.65% |

- LSTM-VAE 的 F1 为约 0.776，低于 LSTM-AE 的约 0.787。
- AP 约低 **0.0097**。
- 召回率约低 **2.04 个百分点**。
- 误报率约低 **0.19 个百分点**。

这表示两者在本次实验中接近：AE 的平均综合表现和检出比例略高，VAE 的平均误报比例略低。

VAE 的 F1 标准差为约 0.012，低于 AE 的约 0.035，可以描述为“本次三次运行的 F1 波动较小”。但样本次数有限，且未进行统计显著性检验，不能扩大成“VAE 已被证明普遍更稳定”。

**本次结果支持时序重构方法在这套合成基准上的价值，没有证明 VAE 一定优于普通 AE。**

## 七、四类异常分别说明了什么？

下表对应主图中四种方法的热图，均为三次平均召回率：

| 方法 | 持续偏移 | 渐进漂移 | 指标关联异常 | 时序模式异常 |
| --- | ---: | ---: | ---: | ---: |
| 固定阈值 | 42.96% | 49.63% | 14.81% | 11.85% |
| 个人 Z-score | 86.67% | 91.85% | 1.48% | 0.74% |
| 孤立森林 | 92.59% | 95.56% | 11.11% | 44.44% |
| LSTM-VAE | 99.26% | 98.52% | 40.00% | 36.30% |

### 7.1 持续偏移与渐进漂移

LSTM-VAE 的召回率分别为 **99.26% 和 98.52%**，说明它在本次设定的数值偏移场景下表现较好。个人 Z-score 和孤立森林也能检出较多这类异常，说明个人基线和简单统计方法本身就有价值。

### 7.2 指标关联异常

LSTM-VAE 为 **40.00%**，高于 Z-score 的 1.48% 和孤立森林的 11.11%，说明序列重构在这类人为错位数据上提供了额外识别能力。

但它仍漏掉约六成此类窗口。适合说“有一定改善”，不适合说“已经可靠识别全部多指标关联异常”。

### 7.3 时序模式异常

LSTM-VAE 为 **36.30%**，低于孤立森林的 **44.44%**。

这一结果表明：使用 LSTM 不保证所有时间模式异常都识别得更好。孤立森林接收了相邻变化等窗口特征，在本次时间重排场景中也能发挥作用。

### 7.4 技术补充：与 LSTM-AE 的分场景对照（不在主图）

| 方法 | 持续偏移 | 渐进漂移 | 指标关联异常 | 时序模式异常 |
| --- | ---: | ---: | ---: | ---: |
| LSTM-AE | 100.00% | 98.52% | 43.70% | 40.00% |
| LSTM-VAE | 99.26% | 98.52% | 40.00% | 36.30% |

两者的渐进漂移平均召回率相同；本次 AE 在其余三类的平均召回率略高。尤其在指标关联异常和时序模式异常上，VAE 分别低于 AE 的 43.70% 和 40.00%，完整结果未显示 VAE 对这些场景有额外优势。

## 八、用一次真实运行理解指标怎样算出来

取随机种子 **11** 的 LSTM-VAE 结果：

- 180 个异常窗口中，找到 117 个，漏掉 63 个。
- 540 个正常窗口中，误报 8 个，正确放过 532 个。

由此得到：

- 召回率：`117 ÷ 180 = 65.00%`。
- 精确率：`117 ÷（117 + 8）= 93.60%`。
- 误报率：`8 ÷ 540 ≈ 1.48%`。
- F1：`2 × 117 ÷（2 × 117 + 8 + 63）≈ 0.7672`。

这是一轮实验的结果。主图显示的是三轮各自算出指标后再取平均，所以主图中的召回率是 68.52%，而不是这里的 65.00%。

不要先把平均精确率、平均召回率代回公式，认为一定能得到完全相同的平均 F1；计算顺序不同，结果可能不同。

## 十、可以直接用于展示的讲解稿

### 10.1 约 3 分钟讲解稿

> 这张图比较 LSTM-VAE 与固定阈值、个人 Z-score、孤立森林三种基础方法识别异常体征片段的表现。数据由程序模拟生成，包含不同个体的正常变化和四类人为加入的异常，所以它是离线算法验证，不是临床准确率证明。
>
> 先说明几个名称。固定阈值检查体征有没有越过预设界限；个人 Z-score 判断数值偏离个人平时水平有多远；孤立森林通过随机切分数据寻找与正常样本不同的窗口。LSTM 是处理时间序列的网络，VAE 是先压缩再还原数据、并用概率分布约束压缩表示的模型。LSTM-VAE 将这两种思路结合，根据还原误差判断异常。
>
> 左边的 F1 综合衡量告警是否判得准、异常是否找得全；AP 衡量不同判定界限下的综合排序表现。右上召回率表示异常找到了多少，误报率表示正常窗口被错判了多少。横线表示三次实验的波动。右下颜色越深，表示对应异常类型的召回率越高。
>
> 三次固定种子实验中，LSTM-VAE 的平均 F1 为 0.776，高于固定阈值的 0.333、个人 Z-score 的 0.591 和孤立森林的 0.643。相比固定阈值，召回率从约 29.81% 提高到 68.52%，误报率从约 16.54% 降到 2.65%。主图中固定规则使用预设界限，其他方法使用验证集选出的界限。
>
> 结果说明，在这些模拟场景中，体征历史和时间变化模式能够补充单点阈值判断。LSTM-VAE 对持续偏移和渐进漂移检出较好，指标关联与时间重排仍有较多漏检；图中体现的是它相对这三种基础方法的整体表现，实际老人监测效果还需要真实数据验证。

### 10.2 已解释过术语后，可用的简短结论

> 在三个固定随机种子的合成数据实验中，LSTM-VAE 的 F1 为 0.776、AP 为 0.866，均高于图中固定阈值、个人 Z-score 和孤立森林三种基础方法。它对持续偏移和渐进漂移检出较好，复杂关联与时间重排仍有较多漏检。实际老人监测效果还需要真实数据验证。

## 十一、评委可能追问的问题

### 11.1 “0.776 是不是你们的健康评分准确率？”

不是。它是窗口异常识别的 F1，综合精确率和召回率。这个实验没有给每位老人标注一个真实的 0～100 健康分，所以不能用它证明健康分数本身的医学准确性。

### 11.2 “既然还要选阈值，模型与阈值方法有什么区别？”

两者都可以有最终的分界线。区别在于分界线作用的对象：固定规则直接比较体征数值；序列模型先从一段多指标数据中计算重构异常程度，再判断这个程度是否足够大。使用学习到的异常分数，不等于完全取消阈值。

### 11.3 “除了主图中的基础方法，有没有与 LSTM-AE 做对照？”

有。完整实验保留了 LSTM-AE，结果见第 6.5、7.4 节的技术补充及 JSON。加入 AE 是为了检查 VAE 的额外设计是否确实带来收益。本次 AE 的平均 F1/AP 略高，VAE 的平均误报率略低。当前证据不足以说 VAE 更好；主图聚焦与三种基础方法的比较，不代表全部模型的排名。

### 11.4 “是否已经实现提前预警？”

本图展示的是整个窗口是否被正确识别，没有测量连续监护中的首次发现时间。识别出渐进漂移只能说明该类窗口被检出，不能据此宣称提前了多少分钟。

### 11.5 “模拟数据是不是让模型容易赢？”

模拟规律和异常类型的选择会影响成绩，这是实验的局限。我们预先确定了数据生成方法、种子和比较方法，保留所有运行与所有方法的结果。后两类异常特意考察数值范围之外的模式变化，因此结论限定在这些合成场景，不能泛化成对所有疾病和异常都更好。

### 11.6 “下次演示为什么不用等模型重新训练？”

已经把每轮标签、各方法分数、判定界限和评价结果保存在 JSON 缓存中。正常运行 `detector.py` 时，程序先检查这份记录；记录有效就直接出图并自动打开，没有有效记录才重新运行对比。默认终端只显示准备和图片就绪提示；加 `--verbose` 才显示缓存判断和执行明细，加 `--no-open` 可只保存图片。

入口自动识别当前脚本文件名；计算内容和参数不变时，连同缓存一起移动目录或重命名入口不会触发重新训练，模型、数据、评估或参数变化仍会使缓存失效。

本机此前完整训练与评估约 30.6 秒，缓存回放与重绘约 1.04 秒，后者不含图片查看器启动。JSON 保留原实验时间和来源；读取缓存是在展示已完成的实验，不应讲成“现场一秒完成了训练”。

## 十二、展示时保留的结论边界

1. 说“合成体征异常识别实验”，不把模拟对象数当成真实受试老人数量。
2. 说“F1、AP、召回率、误报率”，不要统称为同一个准确率。
3. 说“F1、AP 高于主图所列三个基础方法”，各场景差异和 AE 技术对照可在完整记录中核查。
4. 说“在本次设置下有改善”，不宣称已经证明临床有效、提前预警或全面替代规则。
5. 把“检测出的异常程度”和“医学健康程度”分开说明。

**最稳妥的一句话：这张图为“利用个人历史和时序模式补充固定阈值”提供了可复现的合成实验依据，实际使用价值还需要进一步验证。**
